Самостійна робота No9

• Тема: Делегати й лямбда-вирази: власні утиліти для колекцій.
• Обсяг: 80 хв (2 академічні години)

Мета

Поглибити розуміння делегатів та лямбда-виразів через створення власних узагальнених методів-
утиліт для роботи з колекціями та повторного використання логіки.

1. Чому делегати корисні для створення таких утиліт?
Делегати (Func, Predicate, Action) дозволяють передавати логіку (поведінку) як параметр усередину методів. Завдяки цьому клас CollectionUtils стає універсальним: нам не потрібно писати окремі методи для фільтрації чи перетворення кожного специфічного типу даних. Один метод Filter або Map здатний працювати з будь-якими колекціями та довільними бізнес-правилами, які визначаються під час виклику.

2. Як лямбда-вирази спрощують виклик цих методів?
Лямбда-вирази надають лаконічний і читабельний синтаксис для створення анонімних методів «на льоту». Замість того, щоб вручну створювати окремі класи з інтерфейсами чи іменовані методи-обробники для кожної простої перевірки (наприклад, p => p.Price > 1000), ми можемо передати логіку безпосередньо в рядок виклику утиліти. Компілятор автоматично виводить типи даних (type inference), що повністю позбавляє від зайвого бойлерплейт-коду.

3. Порівняння власних методів з вбудованими LINQ-операторами
Власні методи (Map, Filter, MaxBy, ForEach) концептуально повністю повторюють вбудовані оператори LINQ (Select, Where, MaxBy, а також метод ForEach для списків):

Схожість: Усі вони базуються на ідеї функцій вищого порядку, приймають делегати та оперують узагальненими типами (IEnumerable<T>).

Відмінність (Ліниві обчислення): Більшість стандартних операторів LINQ (окрім ForEach) використовують відкладені (ліниві) обчислення завдяки ключовому слову yield return. Натомість наші реалізації методів Map та Filter створюють новий список (List<TResult>) і виконують обчислення одразу в момент виклику (eager evaluation). Також у сучасних версіях .NET метод MaxBy є вбудованим у бібліотеку LINQ, що підтверджує правильність нашого проєктування.
