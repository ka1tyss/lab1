Мета 

Дослідити, як принципи інкапсуляції та валідації даних реалізуються в реальних open-source проєктах на C#, а також проаналізувати різні підходи до валідації властивостей. 

1. Обраний проєкт
 
Назва: Newtonsoft.Json (Json.NET)

Посилання на GitHub: https://github.com/JamesNK/Newtonsoft.Json

Аналізовані класи (приклади з репозиторію):

JsonTextReader (розбір JSON-потоку)

JsonProperty (опис метаданих властивостей під час серіалізації)

2. Аналіз інкапсуляції
   
Клас: JsonTextReader
Опис класу: Цей клас відповідає за читання JSON-тексту у вигляді потоку токенів. Він приховує внутрішній буфер та стан сканера від зовнішнього користувача.

Поля:
Внутрішній стан закритий від прямого модифікування (використовуються приватні поля та поля з модифікатором private readonly або internal).

// Приклад інкапсуляції полів у JsonTextReader
private readonly TextReader _reader;
private char[] _chars;
private int _charsUsed;
private int _charPos;

Властивості:
Клас широко використовує властивості для контрольованого читання стану (тільки для читання get без set або з прихованим set). Наприклад, властивість TokenType дозволяє отримати поточний тип токена, але її не можна встановити ззовні.

// Приклад властивості тільки для читання або з приватним/захищеним доступом
public override JsonToken TokenType { get; protected set; }
public override object Value { get; protected set; }

Індексатори/Оператори:
У цьому класі індексатори не використовуються, оскільки він орієнтується на потокове читання (Stream/TextReader), а не на довільний доступ за індексом.

Клас: JsonProperty
Опис класу: Описує правила серіалізації конкретної властивості об'єкта (ім'я, тип, наявність конвертерів тощо).

Поля:
Усі базові параметри інкапсульовані через захищені або приватні поля, до яких звертаються через чітко визначені властивості.

Властивості:
Активно використовуються стандартні автоматичні властивості (auto-properties) для простих даних, а також властивості з повною реалізацією (з логікою у get/set), якщо потрібно змінювати внутрішні прапорці чи кешовані значення.

// Приклад автоматичних та налаштовуваних властивостей у JsonProperty
public string PropertyName { get; set; }
public Type PropertyType { get; set; }
public bool Ignored { get; set; }

3. Практики валідації у властивостях

У бібліотеках високого рівня надійності (таких як Newtonsoft.Json) валідація найчастіше реалізується безпосередньо у set-аксесорах властивостей або через захищені методи ініціалізації шляхом викидання винятків при передачі некоректних аргументів.

Приклад 1: Валідація лічильників та розмірів буфера (перевірка на негативні значення)

У класах читання/буферизації бібліотеки впроваджено захист від некоректних параметрів конфігурації. Якщо передати від'ємне число або нуль там, де це неприпустимо, одразу викидається виняток ArgumentOutOfRangeException.


// Фрагмент прикладу валідації у сеттерах або методах ініціалізації
public int LineNumber
{
    get => _lineNumber;
    set
    {
        if (value < 0)
        {
            throw new ArgumentOutOfRangeException(nameof(value), "Line number cannot be negative.");
        }
        _lineNumber = value;
    }
}

Приклад 2: Захист від передачі нульових посилань (null-валідація)

Під час налаштування середовища серіалізації або передачі обов'язкових об'єктів конфігурації використовується стандартна перевірка ArgumentNullException.

// Фрагмент прикладу валідації посилань
public void SetValue(object target, object value)
{
    if (target == null)
    {
        throw new ArgumentNullException(nameof(target));
    }
    // Подальша логіка присвоєння
}

Висновки щодо валідації:

Використання ранньої валідації у властивостях (fail-fast підхід) через стандартні винятки (ArgumentException, ArgumentNullException, ArgumentOutOfRangeException) дозволяє зупинити виконання програми на найранішому етапі при передачі невалідних даних. Це повністю запобігає появі прихованих помилок (наприклад, NullReferenceException чи IndexOutOfRangeException) у глибших шарах коду.
