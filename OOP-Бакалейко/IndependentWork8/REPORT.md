# Звіт до Самостійної роботи №8
**Тема:** Вивчення Dictionary<TKey, TValue> та HashSet<T> у бібліотеках .NET

---

## 1. Результати аналізу open-source проєктів

Під час аналізу популярних .NET бібліотек (на прикладі вихідного коду .NET Runtime та відомих NuGet-пакетів) було досліджено такі приклади використання колекцій:

1. **Використання `Dictionary<TKey, TValue>` (наприклад, у Newtonsoft.Json або Entity Framework Core):**
   - **Контекст:** Зберігання та кешування метаданих типів (Type Descriptors / Reflection Cache). При серіалізації об'єктів бібліотека перевіряє наявність властивостей класу. Щоб щоразу не виконувати повільну рефлексію, результати кешуються у словнику, де ключем є `Type`, а значенням — список властивостей.
   - **Чому обрано Dictionary:** Забезпечує миттєвий пошук O(1) за типом даних, що критично важливо для продуктивності серіалізатора.
   - **Складність:** Пошук і вставка працюють за O(1) у середньому.

2. **Використання `HashSet<T>` (наприклад, у компіляторі Roslyn або Entity Framework Core для відстеження сутностей):**
   - **Контекст:** Відстеження вже оброблених сутностей (Tracker) або виявлення циркулярних посилань під час обходу графів об'єктів. `HashSet` гарантує, що кожен об'єкт буде додано лише один раз.
   - **Чому обрано HashSet:** Забезпечує швидку перевірку наявності елемента за O(1) без дублювання даних.
   - **Складність:** Перевірка `Contains` та додавання — O(1).

3. **Комбіноване використання `Dictionary<TKey, HashSet<T>>` (наприклад, у маршрутизаторах ASP.NET Core або Dependency Injection контейнерах):**
   - **Контекст:** Реєстрація залежностей або мапінг маршрутів, де одному ключу (наприклад, HTTP-методу або імені сервісу) відповідає множина унікальних обробників чи тегів.
   - **Чому обрано комбінацію:** `Dictionary` дозволяє швидко знайти групу за ключем O(1), а `HashSet` усередині значення гарантує відсутність дублікатів і швидке додавання/видалення елементів усередині цієї групи.

## 2. Висновки про вибір колекції

- **Коли Dictionary краще за List?**
  Коли вам потрібно часто здійснювати пошук, оновлення чи видалення елементів за унікальним ідентифікатором (ключем). У `List` пошук працює за лінійний час O(n), тоді як у `Dictionary` — за константний час O(1).
- **Коли HashSet є оптимальним вибором?**
  Коли головною вимогою є гарантія унікальності елементів та швидка перевірка їх наявності (`Contains`). Також `HashSet` незамінний для математичних операцій над множинами (об'єднання `UnionWith`, перетин `IntersectWith`, різниця `ExceptWith`).
- **Які підводні камені при використанні?**
  1. *Колізії хеш-кодів:* Неправильно реалізовані методи `GetHashCode` та `Equals` можуть призвести до деградації продуктивності словників/множин до O(n).
  2. *Зміна ключів:* Зміна значень властивостей об'єкта, які використовуються як ключі у `Dictionary` або елементи в `HashSet`, призведе до того, що елемент стане «невидимим» для пошуку.
  3. *Споживання пам'яті:* Колекції на основі хеш-таблиць виділяють більше пам'яті, ніж прості списки `List<T>`, через внутрішні структури вирівнювання та масиви хешів.

## 3. Приклади з власного коду

У межах практичної частини роботи було реалізовано три компоненти:
1. **`FileMetadataCache` (на базі `Dictionary`):** Забезпечує швидке кешування та пошук метаданих файлів за їхнім шляхом.
2. **`TagManager` (на базі `Dictionary<string, HashSet<string>>`):** Дозволяє керувати тегами статей, виконувати об'єднання всіх тегів та знаходити спільні теги між статтями через операцію перетину множин (`IntersectWith`).
3. **`SearchIndex` (на базі інвертованого індексу `Dictionary<string, HashSet<int>>`):** Здійснює повнотекстовий пошук документів за окремими словами та множинами слів (логічне AND через перетин множин ідентифікаторів документів).
